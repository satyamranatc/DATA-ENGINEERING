Big Data & Spark Architecture

Why distributed computing? How Spark is built internally.

Big Data refers to datasets too large or fast-moving to be processed on a single machine. Apache Spark solves this by splitting work across a cluster of machines.

Why not Pandas for big data?
PandasPySpark
Single machine (RAM-bound)Distributed across many nodes
Processes MBs to low GBsProcesses GBs to PBs
Eager evaluationLazy evaluation (optimized)
No fault toleranceAutomatic failure recovery
Spark Architecture
Spark Cluster Layout
Driver Program (your PySpark script)
|
|--- SparkContext / SparkSession
|
Cluster Manager (YARN / Kubernetes / Standalone)
|
|--- Worker Node 1 ---> Executor ---> Tasks
|--- Worker Node 2 ---> Executor ---> Tasks
|--- Worker Node N ---> Executor ---> Tasks
  • Driver — your script; orchestrates the job, creates the execution plan
  • Executor — JVM processes on worker nodes that run Tasks
  • Task — the smallest unit of work, processes one data partition
  • Partition — a chunk of your data (default ~128 MB each)
i
Local mode On your laptop, PySpark runs in "local mode" — simulating multiple cores without a real cluster. Perfect for development and learning.

Installation & SparkSession

Set up PySpark locally and create your first SparkSession

SparkSession is the single entry point to all Spark functionality. You create one at the start of every PySpark program.

Terminal 
pip install pyspark
spark_session.py 
from pyspark.sql import SparkSession

# Create (or get existing) SparkSession
spark = SparkSession.builder \
    .appName("MyFirstSparkApp") \
    .master("local[*]") \        # use all CPU cores locally
    .config("spark.sql.shuffle.partitions", "4") \
    .getOrCreate()

print(spark.version)          # e.g. 3.5.0

# Always stop the session when done
spark.stop()
Builder OptionWhat it does
.appName("name")Label shown in the Spark UI
.master("local[*]")Run locally using all cores; use local[4] for 4 cores
.config(k, v)Set any Spark configuration property
.getOrCreate()Return existing session if one is already running
03

Spark DataFrames

Reading data, inspecting schemas, and basic actions

A Spark DataFrame is a distributed collection of rows with named, typed columns — similar to a Pandas DataFrame but partitioned across the cluster.

dataframes.py 
from pyspark.sql import SparkSession

spark = SparkSession.builder.appName("DataFrames").master("local[*]").getOrCreate()

# ── Create a DataFrame from a Python list ──────────────
data = [
    ("Alice", "Sales",   55000),
    ("Bob",   "Eng",     90000),
    ("Carol", "Sales",   62000),
    ("Dave",  "Eng",     85000),
    ("Eve",   "HR",      48000),
]
columns = ["name", "dept", "salary"]

df = spark.createDataFrame(data, columns)

# ── Inspect the DataFrame ──────────────────────────────
df.printSchema()       # column names + types
df.show()              # print first 20 rows
df.show(3)             # print first 3 rows
print(df.count())      # total row count (action)
print(df.columns)      # ['name', 'dept', 'salary']
df.describe().show()   # summary statistics

# ── Read a CSV file ────────────────────────────────────
df_csv = spark.read \
    .option("header", "true") \
    .option("inferSchema", "true") \
    .csv("sales_data.csv")

spark.stop()
!
Transformations vs Actions Methods like filter(), select(), groupBy() are transformations — they are lazy and build a plan. Methods like show(), count(), collect() are actions — they trigger actual computation.
04

Transformations, Aggregations & Joins

Filter, select, group, aggregate, and join DataFrames
transformations.py 
from pyspark.sql import SparkSession
from pyspark.sql import functions as F

spark = SparkSession.builder.appName("Transforms").master("local[*]").getOrCreate()

data = [("Alice","Sales",55000),("Bob","Eng",90000),
        ("Carol","Sales",62000),("Dave","Eng",85000),("Eve","HR",48000)]
df = spark.createDataFrame(data, ["name","dept","salary"])

# ── Select columns ─────────────────────────────────────
df.select("name", "salary").show()

# ── Filter rows ────────────────────────────────────────
df.filter(F.col("salary") > 60000).show()
df.filter((F.col("dept") == "Sales") & (F.col("salary") > 55000)).show()

# ── Add a new column ───────────────────────────────────
df = df.withColumn("salary_usd", F.col("salary") * 1.2)
df = df.withColumn("level", F.when(F.col("salary") >= 80000, "Senior").otherwise("Junior"))

# ── Sort ───────────────────────────────────────────────
df.orderBy(F.col("salary").desc()).show()

# ── Group By + Aggregation ─────────────────────────────
df.groupBy("dept").agg(
    F.count("name").alias("headcount"),
    F.avg("salary").alias("avg_salary"),
    F.max("salary").alias("max_salary")
).show()

# ── Join two DataFrames ────────────────────────────────
dept_data = [("Sales", "New York"), ("Eng", "San Francisco"), ("HR", "Chicago")]
dept_df = spark.createDataFrame(dept_data, ["dept", "city"])

joined = df.join(dept_df, on="dept", how="inner")
joined.show()

spark.stop()
Window Functions
window_functions.py 
from pyspark.sql import functions as F
from pyspark.sql.window import Window

# Rank employees within each department by salary
window_spec = Window.partitionBy("dept").orderBy(F.col("salary").desc())

df = df.withColumn("rank",         F.rank().over(window_spec)) \
       .withColumn("dept_avg_sal", F.avg("salary").over(Window.partitionBy("dept")))

df.show()
Join TypeKeeps rows from...
innerBoth DataFrames where key matches
leftAll rows from left; NULLs for non-matching right
rightAll rows from right; NULLs for non-matching left
outerAll rows from both; NULLs where no match
05

Spark SQL

Query DataFrames using standard SQL syntax

Register any DataFrame as a temporary view, then query it with plain SQL. Both the DataFrame API and Spark SQL produce identical execution plans under the hood.

spark_sql.py 
from pyspark.sql import SparkSession

spark = SparkSession.builder.appName("SparkSQL").master("local[*]").getOrCreate()

data = [("Alice","Sales",55000),("Bob","Eng",90000),
        ("Carol","Sales",62000),("Dave","Eng",85000)]
df = spark.createDataFrame(data, ["name","dept","salary"])

# Register as a SQL view
df.createOrReplaceTempView("employees")

# Run SQL queries
result = spark.sql("""
    SELECT dept,
           COUNT(*)       AS headcount,
           AVG(salary)    AS avg_salary,
           MAX(salary)    AS top_salary
    FROM   employees
    GROUP  BY dept
    ORDER  BY avg_salary DESC
""")

result.show()

# Filtering with SQL
spark.sql("SELECT name, salary FROM employees WHERE salary > 80000").show()

# Result is a regular DataFrame — chain more transformations
result.filter(result.avg_salary > 60000).show()

spark.stop()
+
Tip Use createOrReplaceTempView for session-scoped views. Use createGlobalTempView + prefix global_temp. to share a view across sessions.

Lazy Evaluation, Partitions & Performance

Understand how Spark actually runs your code and how to optimize it
Lazy Evaluation

Spark does not execute transformations immediately. It builds a logical plan (a DAG of operations) and only runs it when an action is triggered. This allows Spark to optimize the entire pipeline before executing.

performance.py 
from pyspark.sql import SparkSession
from pyspark.sql import functions as F

spark = SparkSession.builder.appName("Perf").master("local[*]").getOrCreate()

df = spark.read.csv("large_sales.csv", header=True, inferSchema=True)

# ── Explain the execution plan ─────────────────────────
df.filter(F.col("amount") > 1000).explain()          # physical plan
df.filter(F.col("amount") > 1000).explain(True)    # full plan

# ── Check partition count ──────────────────────────────
print(f"Partitions: {df.rdd.getNumPartitions()}")

# ── Repartition (increases parallelism) ───────────────
df_repartitioned = df.repartition(8)

# ── Coalesce (reduce partitions without full shuffle) ─
df_coalesced = df.coalesce(2)

# ── Cache a DataFrame reused multiple times ───────────
df.cache()       # keeps in memory after first action
df.count()       # triggers caching
df.show(5)       # served from cache — fast!
df.unpersist()   # release memory when done

spark.stop()
ConceptWhat it meansWhen to use
Narrow transformationEach input partition produces exactly one output partition (e.g. filter, select)No data movement needed — fast
Wide transformationData must be shuffled across partitions (e.g. groupBy, join)Expensive — minimize shuffles
cache()Store DataFrame in memoryWhen you reuse a DataFrame multiple times
repartition(n)Redistribute data into n partitions (full shuffle)Increase parallelism before heavy operations
coalesce(n)Reduce partitions (no full shuffle)Before writing output to reduce file count
!
Avoid collect() on large data df.collect() brings all data to the Driver. On large datasets this causes Out-of-Memory errors. Use show() or take(n) instead.

Reading & Writing File Formats

CSV, JSON, and Parquet — the three most common data engineering formats
file_formats.py 
from pyspark.sql import SparkSession

spark = SparkSession.builder.appName("FileFormats").master("local[*]").getOrCreate()

# ── CSV ────────────────────────────────────────────────
df_csv = spark.read \
    .option("header",      "true") \
    .option("inferSchema", "true") \
    .option("sep",          ",") \
    .csv("data/sales.csv")

df_csv.write.mode("overwrite").csv("output/sales_out")

# ── JSON ───────────────────────────────────────────────
df_json = spark.read.json("data/events.json")
df_json.write.mode("overwrite").json("output/events_out")

# ── Parquet (recommended for data engineering) ─────────
# columnar format — much faster for analytics queries
df_csv.write.mode("overwrite").parquet("output/sales.parquet")

df_parquet = spark.read.parquet("output/sales.parquet")
df_parquet.show(5)

# ── Write with partitioning (like folders by date) ────
df_csv.write \
    .mode("overwrite") \
    .partitionBy("dept") \
    .parquet("output/sales_partitioned")

spark.stop()
FormatBest forCompressionSchema stored
CSVSimple exchange, debuggingNoNo
JSONNested / semi-structured dataNoNo
ParquetAnalytics, data lakes, warehousesYes (snappy)Yes
*
Always prefer Parquet in production Parquet is columnar — it reads only the columns your query needs, dramatically reducing I/O. It also stores schema and supports Snappy compression by default.

Mini Project — Large-Scale Sales Data Processing

End-to-end PySpark pipeline: ingest, clean, transform, aggregate, and export

This project brings together every concept from this module into a single production-style pipeline.

sales_pipeline.py 
"""
Module 7 Mini Project: Large-Scale Sales Data Processing Pipeline
"""
from pyspark.sql import SparkSession
from pyspark.sql import functions as F
from pyspark.sql.window import Window


def build_spark():
    return SparkSession.builder \
        .appName("SalesPipeline") \
        .master("local[*]") \
        .config("spark.sql.shuffle.partitions", "4") \
        .getOrCreate()


def ingest(spark, path: str):
    """Read raw CSV and enforce schema."""
    return spark.read \
        .option("header", "true") \
        .option("inferSchema", "true") \
        .csv(path)


def clean(df):
    """Remove nulls, duplicates, and invalid rows."""
    return df \
        .dropna(subset=["order_id", "amount"]) \
        .dropDuplicates(["order_id"]) \
        .filter(F.col("amount") > 0)


def transform(df):
    """Add derived columns and categorize."""
    window = Window.partitionBy("region").orderBy(F.col("amount").desc())

    return df \
        .withColumn("year",  F.year("order_date")) \
        .withColumn("month", F.month("order_date")) \
        .withColumn("tier",
            F.when(F.col("amount") >= 10000, "Enterprise")
             .when(F.col("amount") >= 1000,  "Mid-Market")
             .otherwise("SMB")) \
        .withColumn("rank_in_region", F.rank().over(window))


def aggregate(df):
    """Summarize by region and tier."""
    return df.groupBy("region", "tier").agg(
        F.count("order_id").alias("order_count"),
        F.sum("amount").alias("total_revenue"),
        F.avg("amount").alias("avg_order_value"),
    ).orderBy("region", F.col("total_revenue").desc())


def export(df, output_path: str):
    """Write result as Parquet, partitioned by region."""
    df.write \
      .mode("overwrite") \
      .partitionBy("region") \
      .parquet(output_path)
    print(f"Exported to {output_path}")


# ── Run the pipeline ───────────────────────────────────
if __name__ == "__main__":
    spark = build_spark()

    raw_df      = ingest(spark, "data/sales_raw.csv")
    clean_df    = clean(raw_df)
    clean_df.cache()                     # reused below — cache it

    enriched_df = transform(clean_df)
    summary_df  = aggregate(enriched_df)

    summary_df.show(20)
    export(summary_df, "output/sales_summary")

    clean_df.unpersist()
    spark.stop()
